# Claude Code Instructions

## Code style

All code in this repository (TypeScript, CSS and HTML) must follow
[CONTRIBUTING.md](CONTRIBUTING.md). Read it before writing or modifying any code.

Rules that are easy to miss:

- **Allman braces everywhere**, including single-statement `if` bodies and CSS rules
- **A blank line before every `return`**
- **Every function name starts with a verb**: `renderGenusPage`, not `genusPage`
- **Helpers are `function` declarations**, not arrows assigned to a variable; arrows only for
  short callbacks passed to an API
- **Plain loops over `map`/`filter`/`reduce`** on anything that runs per record; no functions
  declared inside loops
- **No anonymous object types**; every returned object has a named `type`
- **`type` not `interface`, `Array<T>` not `T[]`**, no `any`
- **No abbreviated names**: `element`, `reference`, `index`, `event`, `initialize`
- **American English** in code, comments, docs and site copy
- **Multi-line JSDoc** on every function, type and type field
- **Exact dependency versions**; no `^` or `~` in `package.json`, and pick releases at least
  two weeks old (Open Paleo's own packages, such as the tree extractor, are exempt)
- **No browser dependencies** other than MapLibre GL JS (the maps) and the tree extractor with
  Tesseract.js (the tool page), each loaded only where it is used; every page but the tool
  works with JavaScript off

Astro components (see "Astro components" in CONTRIBUTING.md):

- The frontmatter follows every TypeScript rule; every component that takes properties
  declares a `Props` type
- `map` with an arrow is allowed only in template markup, and only to output one element
- Data work (sorting, grouping, look-ups, formatting) goes in `src/data/`, not in components
- Never `set:html` on dataset text
- Styles go in the component's own `<style>` block; `src/theme/` is for global tokens and
  element defaults only

Run `npm run typecheck`, `npm run lint`, `npm run spellcheck`, `npm test`, `npm run build` and
`npm run check-site` before considering code complete (`check-site` needs Chromium once:
`npx playwright install --only-shell chromium`). Don't pipe them through `tail` when checking the
result: the pipe hides the exit code.

## Theme

The site uses the Strata theme, documented in [docs/theme.md](docs/theme.md).

- No literal colors outside `src/theme/tokens.css`. A new color is a new token, defined on bare
  `:root` and, if it changes in dark mode, redefined identically in both dark blocks
- Geologic time colors are used only in age graphics
- Every genus and species name gets `class="taxon"` (italic); clade names stay roman
- No all-caps labels, no decorative numbering, and no monospace except for code (the BibTeX
  entries)

## Data

- The site reads only `dist/open-paleo.json` from open-paleo/data, the versioned output
  contract. Never read the data repository's source YAML
- Pages get data through `getSiteData()` in `src/data/site-data.ts`; types come from
  `src/data/dataset.ts`. `src/data/bindings/` is generated by `npm run update-bindings`
- Tests use `test/fixtures/open-paleo.json`, cut from real data by
  `npm run create-test-fixture`; never invent records for tests
- If the site needs something that is not in `dist/`, raise it as a change to the data
  repository's build; do not work around the contract
- Never write a fact about a taxon into a template or into copy. Every value comes from the
  dataset
- **Never edit, commit or push in open-paleo/data from this repository.** Raise what the site
  needs with that repository's maintainers (or its own Claude Code session), and let them make
  the change there

## Git workflow

**Do not commit or push unless explicitly told to.** Show the changes and wait for the user to
say to commit or push.

## Generated output

The generated site goes in `dist/` (`public/` is Astro's folder of static files copied as-is),
and reports and working files go in `scratch/`. Neither `dist/` nor `scratch/` is ever
committed. Anything in `scratch/` worth keeping belongs in a GitHub issue.
